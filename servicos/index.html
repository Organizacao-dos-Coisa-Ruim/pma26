    Microsserviços

    Todos rodam na porta 8080 dentro do container, expõem GET /<recurso>/health-check e métricas em /actuator/prometheus. Só o gateway é acessível de fora. Contrato completo das rotas: API (OpenAPI).

    Gateway

    gateway-service · Spring Cloud Gateway (WebFlux)

    • Roteia por prefixo: /auth/**, /accounts/**, /exchange/**, /products/**, /orders/**.
    • AuthorizationFilter: nas rotas protegidas, valida o JWT chamando POST /auth/solve e repassa id-account / role-account em headers. Também barra rotas só de admin (RBAC).
    • SecurityHeadersFilter: adiciona headers de segurança em toda resposta (scan de vulnerabilidades).
    • É o deployment escalado pelo HPA (load test).

    Auth

    pma26-auth · pma26-auth-service

    Rota O que faz
    POST /auth/register cria a conta (chama o Account via Feign)
    POST /auth/login confere a senha no Account e devolve um JWT com sub = id da conta e role
    POST /auth/solve valida o JWT e devolve idAccount e role (usado só pelo gateway)

    O Auth não tem banco: os dados do usuário ficam no Account.

    Account

    pma-26-account · pma26-account-service

    CRUD de usuários (nome, email, senha com BCrypt), schema account no PostgreSQL (Flyway). Um usuário só vê a própria conta; listar e apagar contas é só para admin. O admin inicial é criado a partir de variáveis de ambiente (AdminBootstrap).

    Exchange

    pma26-exchange · pma26-exchange-service

    GET /exchange/{de}/{para} devolve a cotação entre duas moedas (ex.: USD/BRL), consultando a AwesomeAPI. A cotação fica em cache no Redis por 5 minutos (gargalo). Será usado pelo Order para mostrar o total do pedido em outra moeda.

    Product

    product · product-service

    Catálogo de produtos no formato do enunciado (id, name, price, unit), schema products no PostgreSQL (Flyway). Rotas: POST /products, GET /products, GET /products/{id} e DELETE /products/{id}. Os campos são validados com Bean Validation (@Valid na interface), com limites iguais aos das colunas, então dado inválido vira 400 e não 500. O Order consulta GET /products/{id} via Feign para montar o pedido.

    Order

    order · order-service

    Pedidos, schema orders no PostgreSQL (Flyway).

    Rota O que faz
    POST /orders cria um pedido: {"items": [{"productId": "...", "quantity": 3}]}
    GET /orders, GET /orders/{id} pedidos da conta logada (pedido de outra conta → 403)

    Ao criar um pedido, o Order não confia no preço enviado pelo cliente: para cada item ele chama o Product via Feign (GET http://product:8080/products/{id}), guarda nome e preço unitário daquele momento e calcula subtotal e total. Produto inexistente ou id recusado pelo Product → 404; Product fora do ar → 503. O dono do pedido vem do header id-account, que o gateway preenche a partir do JWT.
